## Goal

Make the switch-shaped dispatch work at every level of the command tree, in the
spelling proposed in `SUBCOMMANDS-DISPATCHER.md`:

```zig
if (CLI.command(cli)) |cmd| switch (cmd) {
    .body => |b| {
        if (CLI.command(b)) |subcmd| switch (subcmd) {
            .left => |l| expr,
            .right => |r| some_statement,
        } else { /* ... */ }
    },
}
```

The same namespace-level `command` must accept the root `View` and any nested
sub-`View` and return that level's payload union. No declaration syntax changes,
no `View` layout changes, no parser changes.

## What exists at HEAD (`2abdabc`)

- `generate` builds the namespace under a local `Base` and, for levels that
  declare commands, returns a forwarding shell (`src/dap.zig:2616-2643`). The
  shell exposes `CommandPayload = CommandPayloadOf(app, cmd_entries)` and
  `pub fn command(view: View) ?CommandPayload`, which `inline for`s the command
  fields and `@unionInit`s the first non-null one.
- `CommandPayloadOf` (`src/dap.zig:2707-2722`) synthesizes the union: tag =
  `c.field`, payload = `Sub(c.Cmd, subApp(app, c)).View` — the exact expression
  the parent `View` stores as `?View`.
- `Sub(c.Cmd, app)` is just `generate(app, Cmd.cmd_def)` (`src/dap.zig:2649-2651`),
  so every command level has the same machinery, including its own `command`
  accessor when it declares commands.
- The child namespace is _not nameable_ from user code: `Sub` is private and
  `generate` returns the shell type only for the root. That is why nested
  dispatch is impossible today: the payload `b` is a plain `View` struct, and
  Zig cannot recover the namespace it was generated by from the value.
- The existing `View` reach-through (`n._nested.?._deep.?.n`) works because the
  `_`-prefixed fields are public struct fields (M7 test at
  `src/dap.zig:4768-4781`, M15 test at `src/dap.zig:6326-6335`).
- `@Struct`-generated `View` types are nominal, not structural. Different
  `generate` instantiations produce distinct types even when every field name
  and type matches. The current code already relies on this (`@FieldType`
  equality tests, `M15: CommandPayload members match the sub-view types`).

## Why the requested snippet does not compile today

`CLI.command` is declared with a concrete parameter type, the root `View`. A
body-level `b` has the body `View` type, which is a different struct, so
`CLI.command(b)` is a type mismatch. `b.command()` does not exist because the
`View` is built with `@Struct` and has fields only. The child namespace is
unreachable by name, so `Body.command(b)` cannot be written either.

## Design

Resolve a `View` type back to the command level it belongs to at comptime, and
make `command` generic over its argument type. Both pieces live in the shell;
nothing new is public except the widened parameter.

### Registry

A private file-level helper, placed beside `CommandPayloadOf`
(`src/dap.zig:2707`), collects every node in the tree in pre-order:

```zig
/// `NS` followed by every command node below it, depth-first in declaration
/// order. Child namespaces are rebuilt with the same `Sub(c.Cmd, subApp(...))`
/// expression `View` and `CommandPayload` use, so the types are identical:
/// Zig caches a generic instantiation per comptime argument tuple.
fn commandNodes(comptime NS: type) []const type {
    comptime {
        @setEvalBranchQuota(1_000_000);
        var nodes: []const type = &[_]type{NS};
        for (NS.commands) |c| {
            nodes = nodes ++ commandNodes(Sub(c.Cmd, subApp(NS.app_meta, c)));
        }
        return nodes;
    }
}
```

This mirrors `collectFlagOrigins` (`src/dap.zig:3476-3504`) and
`appendActiveScopes` (`src/dap.zig:1397-1416`), which already rebuild `Sub(...)`
the same way. The unique-path invariant holds: sibling wire names are unique
per level (`checkCommandNames`, `src/dap.zig:3329`), so two nodes cannot share
`app_meta.name`, hence cannot share a `generate` instantiation, hence cannot
share a `View` type. That is the property the dispatch relies on.

A defensive pairwise check is proposed in **U2**.

### Generic accessor

Replace the shell's `command` (`src/dap.zig:2634-2642`) with:

```zig
pub const CommandPayload = CommandPayloadOf(app, cmd_entries);

/// Every command node of this tree, this level first, in declaration
/// pre-order. A `View` type identifies the level it was parsed from.
const Nodes: []const type = comptime commandNodes(@This());

/// Resolve a `View` type back to its level. A leaf (no further commands) and
/// a foreign view are compile errors, matching the existing `@hasDecl`
/// convention for commandless levels.
fn NodeOf(comptime V: type) type {
    inline for (Nodes) |NS| {
        if (NS.View == V) {
            if (NS.commands.len == 0) {
                @compileError("dap.command: '" ++ NS.app_meta.name ++
                    "' declares no subcommands");
            }
            return NS;
        }
    }
    @compileError("dap.command: argument is not a command View of '" ++ app.name ++ "'");
}

/// Wrap the active subcommand of any level in this tree into that level's
/// payload union; `null` when none was activated. Allocates nothing.
pub fn command(view: anytype) ?NodeOf(@TypeOf(view)).CommandPayload {
    const NS = NodeOf(@TypeOf(view));
    inline for (NS.commands) |c| {
        if (@field(view, c.view_field)) |sub| {
            return @unionInit(NS.CommandPayload, c.field, sub);
        }
    }
    return null;
}
```

The loop moves from `cmd_entries` to `NS.commands`, and the union type from
`CommandPayload` to `NS.CommandPayload`; the body is otherwise byte-for-byte
the old one. The return type is a comptime function of the argument type, which
Zig permits and which lets one declaration serve every level.

`NodeOf` stays private. A private helper used in a public generic signature is
fine: callers can `switch` on the inferred return type without naming the
helper. `pub const CommandPayload` remains for the current level and keeps the
existing `@FieldType` tests meaningful.

Both the root shell and every child shell get the widened accessor
automatically, because they are the same shell. A named child namespace would
also expose `Body.command(b)` (see **U3**), but the requested form only needs
the root accessor.

### Behavior matrix

| Call                                                | Result                                         |
| --------------------------------------------------- | ---------------------------------------------- |
| `CLI.command(root_view)` at a commandless root      | compile error: no member `command` (unchanged) |
| `CLI.command(root_view)` with a root command active | root `CommandPayload` branch, else `null`      |
| `CLI.command(sub_view)` for any non-leaf descendant | that level's `CommandPayload`, else `null`     |
| `CLI.command(leaf_view)`                            | compile error naming the leaf's full path      |
| `CLI.command(0)` / a foreign view                   | compile error naming the root path             |
| `CLI.command(*View)`                                | compile error; see **U1**                      |

Every payload member is still the same `Sub(...).View` the parser stored, so
field access, `deinit`, and existing tests are untouched. Dispatch copies the
view value, exactly like today's root accessor; it does not transfer ownership
and does not change `CLI.deinit(&view, allocator)` semantics.

### Why not the alternatives

- **Wrapper payload carrying a `command` method.** Would make dispatch spelling
  `b.command()`, contradicting the requested form, and would change
  `CommandPayload` member types, breaking M15 and user code.
- **Re-exporting each child namespace as `pub const body = Sub(...)`.** Would let
  users write `CLI.body.command(b)` and name intermediate `View` types, but adds
  a collision surface with fixed namespace members (`parse`, `View`, `command`,
  `deinit`, …) for a spelling the requirement does not ask for. Deferred in
  **U3**.
- **A marker field on `View` carrying a namespace id.** `@Struct` cannot carry
  decls, and an extra field would leak into the public `View`, tests, and
  deinit loops.

## Tests (new M18 block, appended after M17 at `src/dap.zig:6806`)

Add a fixture mirroring the requirement, plus reuse the existing M7 tree:

```zig
const M18Def = .{
    .body = Command(.{ .help = "Body." }, .{
        .left = Command(.{ .help = "Left." }, .{
            .x = Flag(u8){ .long = "x" },
        }),
        .right = Command(.{ .help = "Right." }, .{
            .y = Argument([]const u8){},
        }),
    }),
};
const M18 = generate(App{ .name = "m18", .help = "m18" }, M18Def);
```

- `M18: dispatch through two levels` — parse `body left --x 3`; switch on
  `M18.command(v).?` then `M18.command(b).?`; assert `.left.x == 3`.
- `M18: intermediate view with no active child dispatches to null` — parse
  `body`; assert `M18.command(b) == null`.
- `M18: three levels dispatch through each accessor` — a fixture with
  `body -> left -> go`; parse all three tokens and nest three dispatches.
- `M18: a mid-level view dispatches from the root accessor` — parse
  `--needed v nested deep 5` on M7, then `M7.command(a._nested.?)` resolves
  `.deep` and `d.n == 5` (this is the generic path the old API could not
  express).
- `M18: root flags after a deep handoff still land on the root` — on the M7
  tree, parse `--needed v nested --verbose deep 5`; assert `v.verbose` and the
  nested `.deep` payload through two accessor calls.
- `M18: dispatch does not disturb deinit` — parse a nested view owning a
  string, dispatch, then `M18.deinit(&v, std.testing.allocator)` with no leak
  (proves dispatch copies and never becomes an owner).
- `M18: registry covers the tree and View types are unique` — call the private
  `commandNodes(M18)`, assert one entry per node (root, body, left, right) and
  pairwise `a.View != b.View`.
- `M18: dispatch into a leaf is a compile error` — commented-out (or
  `if (false)`) per the project's compile-fail convention:
  `_ = M18.command(v._body.?._left.?);` must fail with the leaf-path message.
- `M18: dispatch on a non-view is a compile error` — commented-out:
  `_ = M18.command(0);`.

Keep the M15 tests unchanged; `M15: nested commands stay reachable through the
payload` and `M15: command wraps the active sub-view` are the compatibility
proof for the widened signature.

## Risks and mitigations

- **Comptime recursion.** `commandNodes(@This())` calls `Sub(...)`, which
  instantiates the child shell. The child's own `Nodes` decl must stay lazy:
  declare it with an explicit type (`const Nodes: []const type = comptime ...`)
  and never read it from `commandNodes`. If Zig still forces it, precompute the
  child namespaces in a local `[cmd_entries.len]type` array in `generate`
  (the shape of the existing `field_types` block) and let `commandNodes`
  consume that array. Verify by compiling the two-level fixture first.
- **Compile cost.** Registries are only analyzed when `command` is instantiated,
  and only for the levels a user actually dispatches from. Trees are already
  traversed exhaustively by `checkGlobalFlagNames`, so this adds nothing
  asymptotically.
- **Error noise.** `@typeName` of a `@Struct` view is a long field list; the
  foreign-view message therefore names the root path, not the argument type.
- **Identifier collisions.** `Nodes`/`NodeOf` are private and live on the shell;
  command field names never reach namespace scope (they are not re-exported).

## Open questions

- **U1.** Should `command` also accept `*View` and `*const View`? Proposal:
  values only, matching the current accessor and the requested snippet; pointers
  would add an aliasing question for a call that already copies the small
  `View` struct.
- **U2.** Should the registry include the defensive pairwise check that no two
  nodes share a `View` type? Proposal: include it as a comptime guard with a
  clear message; it is provably dead today (unique full paths give unique
  `generate` instantiations) but catches a future regression that would
  otherwise silently dispatch the wrong level.
- **U3.** Should each command field also be re-exported as a namespace
  declaration on the parent (e.g. `pub const body = Sub(...)`), enabling
  `CLI.body.command(b)` and naming `CLI.body.View`? Proposal: defer; the
  requested form needs only the generic accessor, and the export adds a
  collision surface with fixed namespace members.
