## U4 resolution

U4 is answered by the pad: introduce a tag field that makes every level's `View` nominally unique. Name it `__commandN`,
where `N` is a command cursor that bumps for each new command. The double underscore avoids collisions with command
`View` fields (which start with a single `_`).

That is what landed. No open questions remain.

## What landed

### The cursor

`N` is the level's pre-order rank in the whole command tree: the root is `0`, the first command is `1`, and each
following command node gets the next number. Pre-order means a command's rank is its index in the existing
`commandNodes` registry, so the numbering is stable and total.

The rank is threaded structurally, with no mutable comptime cursor:

- `normalizeRanked(def, base_rank)` numbers the commands of a level. The first child is `base_rank + 1`; each next
  sibling adds `1 +` the number of command nodes in the preceding sibling's subtree.
- `commandSubtreeCount(def)` counts those nodes by walking the raw `Command(...)` fields recursively. It never calls
  `generate`, so it cannot recurse into instantiation.
- `CommandEntry` gained `.rank`.
- `subApp(parent, c)` sets the child's rank to `c.rank`; `App` gained an internal `._command_rank: usize = 0` field
  carrying it. User `App{...}` literals are unaffected because it defaults to `0`; the root is rank `0`.
- `normalize(def)` still means `normalizeRanked(def, 0)`, so every existing caller and test keeps its meaning.
  `collectFlagOrigins` re-normalizes child declarations only for flag tables, where ranks are unused.

### The tag field

Every generated `View` now carries one extra field:

- name: `std.fmt.comptimePrint("__command{}", .{app._command_rank})`;
- type: `u0`, so it is zero-sized and adds nothing to the layout;
- position: after the spec fields and before the `Alt`/command fields. That keeps `builtin_help` first, keeps
  `Alt`/command fields trailing, and leaves the documented field order otherwise intact.

Collision-freedom is structural: declaration field names cannot start with `_`, so command `View` fields always start
with a single `_` and can never be `__commandN`. Two different levels also cannot share a rank because the numbering is
a bijection onto the pre-order nodes.

`deinit` iterates `specs`/`alts`/`cmd_entries` by name and never touches the tag; parsing never reads or writes it, so
`var v: View = undefined` stays sound. Help and suggestions never enumerate `View` fields.

### Dispatch

`NodeOf` now matches exactly: no two levels share a `View` type, so the first match is the only match, and the
shape-equivalence argument is no longer needed. The leaf error reports the matched level's own path instead of the
root's, for example:

```
error: dap.command: a leaf View of 'm18 body left' declares no subcommands
```

`commandNodes`, `NodeOf`, the `Command`/`generate` doc blocks, `AGENTS.md` and `AGENTS-SDK.md` now describe the tag
instead of structural sharing. The `checkCommandNodes` guard remains deleted; it was a workaround for a problem that no
longer exists. Its uniqueness assertion now lives in tests, where the invariant is checked rather than assumed.
